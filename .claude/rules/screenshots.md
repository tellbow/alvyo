# Screenshots of finished work

When a new feature or a bug fix changes what users see on the website or in
the app, take a screenshot of it in its new state and show it to the user in
the terminal (skill `screenshot`) before reporting the work as done. Look at
it yourself first: a screenshot has caught bugs that the tests passed.

Not for changes nobody sees: the API alone, infrastructure, docs, tests.
When it is unclear whether a screenshot is worth it (a small text change, a
state that is hard to reach, a change only on a phone), ask the user rather
than deciding alone.
